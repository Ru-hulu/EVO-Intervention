风险与建议顺序

  1. 状态不变样本占 78.50%，模型容易学会照抄。训练集中 3→1 只有 195 条，占 0.132%；3→2 有 2,902 条。应按输入→输出状态变化及回退类别做适度加权采样，并分别报告召回率。窗口数不等于独立异常事件数，过度重复少量恢复片段也会过拟合。
  2. 正式验证尚未接入训练主循环。当前 val_loader 只用于留出验证视频；本次指标由临时检查代码计算。下一步优先加入定期验证：JSON 合法率、三个 ID 字段完整匹配、变化/回退召回率、分阶段进度 MAE，并与“直接复制输入状态”基线比较。
  3. 数字 token 损失不能直接表达进度误差大小。当前 progress 保留 8 位小数，与 JSON 结构和状态字段一起计算交叉熵。较低 loss 可能主要来自学会格式或状态复制。可先评估减少无意义小数位、对进度与变化字段单独统计损失，再决定是否调整监督。
  4. 训练输入与部署输入有差异。训练使用标注的上一时刻状态，部署时通常输入模型自己的预测，错误会逐步累积。采样帧间隔也并非固定 1 秒，而编码器只接收帧顺序，不接收实际时间。应增加闭环评估；暂不改动已确认的采样规则。
  5. 需要验证模型是否真正使用视觉和历史。目前将带 MEM 的视觉特征经随机初始化的适配层作为文本前缀，与 Qwen 原生图像输入格式不同；视觉层冻结。LoRA 可以适配这条路径，但尚无任务准确率证据。应对比真实图像、遮蔽/替换图像、无历史输入的分组效果。
  6. 进度标签的可预测性需要单独评估。既定 p(t) 使用整条 episode、最后一次成功阶段的 delta 贡献及回滚归一化。当前相似观测可能对应不同的归一化目标；视觉变化也不必然等于任务推进。这是目标定义与观测信息的匹配风险，本次没有修改进度算法。
  7. 长程训练配置还比较简化。没有学习率预热/衰减、梯度累积、最佳验证检查点；恢复会从本轮头部解码并跳过已训练批次，后半轮续训可能等待很久。每 10 步写约 447 MiB 也过于频繁，建议正式训练使用 --save-every 1000，并保持索引与模型权重不变。
  8. 速度、显存与复现仍有约束。未安装 flash-linear-attention / causal-conv1d，日志确认使用 PyTorch 回退实现；LoRA 减少了可训练权重，但仍需保留语言反向激活。batch 2 已用约 50 GiB，不能据此保证 batch 4 可运行。单条 JSON 生成约 2.29 秒，若要每秒更新，需要继续优化。默认 GPU 模式不保证逐位复现。

正式训练命令参考

以下是当前配置下一轮训练的命令参考，本次没有启动这项长程训练。建议先补齐上述分组评估。

source /root/autodl-tmp/qwen35-ft/env.sh
cd /root/autodl-tmp/qwen35-ft/code
python -m qwen_training.train \
  --model-path /root/autodl-tmp/qwen35-ft/models/Qwen3.5-4B \
  --index-files /root/dataset/piperx_insert_copper_screw/samples/samples.jsonl \
    /root/dataset/piperx-bolt-intentional-drop-reinsert-22ep-raw/samples/samples.jsonl \
  --output-dir /root/autodl-tmp/qwen35-ft/outputs/progress-lora \
  --steps 74115 --batch-size 2 --num-workers 4 --val-fraction 0.1 \
  --lora-rank 16 --lora-alpha 32 --lora-dropout 0.05 --lr 1e-4 \
  --save-every 1000 --log-every 20

LoRA 注入与参数保存/加载使用 PEFT 官方接口。本报告记录本次远程实测；临时测试脚本、日志和检查点在完成后清理，仅保留正式代码、依赖、原始数据/模型权重及这份结论。
