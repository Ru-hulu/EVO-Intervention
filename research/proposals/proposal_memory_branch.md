# 实验计划：专用 Gated DeltaNet 记忆分支 + 按项寻址

> 版本：2026-10-23（替换 2026-10-22 版的"监督已有 head 的门"主方案，原方案保留为消融）。主方案见 [proposal_progress.md](proposal_progress.md)，本文件的记忆分支是其中的对照组；背景见 [proposal_streaming_progress_2026-10-22.md](../archive/proposal_streaming_progress_2026-10-22.md)（流式单 VLM 进度模型，已归档）与 [latent_memory.md](../literature/latent_memory.md)（固定容量记忆调研）。

## 0. 动机

- Qwen3.5-2B 共 24 层，其中 18 层是 Gated DeltaNet；4B 共 32 层，其中 24 层是 Gated DeltaNet。每层每个 head 维护一个固定大小的记忆矩阵 $S$（128×128）：

  $$S_t = \alpha_t\, S_{t-1}\,(I - \beta_t k_t k_t^\top) + \beta_t\, v_t k_t^\top$$

  - $\beta_t=\sigma(W_b x_t)$：写入强度，沿 $k_t$ 方向把旧值换成新值；
  - $\alpha_t=\exp(-A\cdot\mathrm{softplus}(W_a x_t+b_{dt}))$：整体衰减，决定遗忘速度。
- 这正是进度任务需要的记忆：子任务完成时更新计数 k，回退时改回去，切换子任务时清掉过时的局部信息。但预训练的 α、β 只为语言建模端到端学出，没有人规定"什么时候写、写什么、忘什么"。
- 2026-10-22 的 RoboDojo 测量（第 11 节）给出两个关键事实：
  - 有 10%–20% 的 head 对视觉 token 的 α 接近 1，按 α 算能保留 30 秒以上；
  - 但算上 β 后，这些 head 的写入在 1–5 秒内就只剩 2%–30%。**遗忘的主因是 β 擦除，不是 α 衰减**：每帧约 590 个视觉 token 写入 128 维的 key 空间，前一帧的内容在重叠方向上被覆盖。
- 结论：只监督已有 head 的门，解决不了"写入次数远超容量"的问题，还会和预训练功能冲突。主方案改为**新增专用记忆分支**：只让每帧一个摘要 token 写入，key 由"正在做哪一项"决定。
- 调研中没有找到直接监督 DeltaNet / Mamba 门的工作；相关工作（Gated DeltaNet-2、Erase-then-Delta）只改门的结构。最接近的是 PACE 对示范注意力的训练期监督，以及 MemBodied 的外置门控关联记忆。

## 1. 要回答的问题

1. 预训练 head 里有没有已经在事件处"用力写"、且能读出 k 的 head？（阶段 A）
2. 专用记忆分支 + 按项寻址，能否让 k 在长间隔、多次重复、回退之后保持正确？
3. 长度外推：训练覆盖 N 次重复，测试 2N、4N 次时是否仍然正确？
4. full attention 只看最近几帧时，记忆分支能否独立承担长程信息？
5. 对结果不可见的重复，加入本体和动作信号后能否写对？

## 2. 主方案概览

每步（5 Hz）追加的序列：

```
[当前帧三视角 patch tokens] · [PROPRIO] · [SUM] · [CNT] [STG] [P] [M]
```

- `[PROPRIO]`：夹爪状态、末端位姿、最近一个动作块的编码。
- `[SUM]`：帧摘要 token，**记忆分支中唯一的写入者**。
- 4 个 readout 头保持不变，读取的是 `[SUM]` 写入之后的记忆。

结构（以 2B 为例）：

```
主干层 L（DeltaNet 或 Full Attn，参数基本冻结 / LoRA）
   │
   ├──► 原 token mixer ───────────────────────────┐
   │                                             + ──► FFN ──► 下一层
   └──► 记忆分支（新增 Gated DeltaNet，零初始化输出）┘
          · 只有 [SUM] 写入，其余 token 只读
          · key 由按项寻址给出
```

- 记忆分支挂在 2–3 个较深的层上（初始选第 4、5 组的 DeltaNet 层，位置作为超参）。
- full attention 层改为只看"前缀 + 最近 N 帧"（主方案，N 对应 2–4 秒）；全历史作为对照。

## 3. 记忆分支设计

### 3.1 结构与初始化

- 每个分支 h 个 head（初始 4 个），每个 head 一个 $S\in\mathbb R^{d_v\times d_k}$，$d_k=d_v=128$。
- 自己的 $W_q, W_k, W_v, W_a, W_b$、`A_log`、`dt_bias`、输出投影；不使用短卷积（写入者每帧只有一个，不需要局部混合）。
- 初始化为"默认不忘、默认不写"：
  - `A_log` 很小、`dt_bias` 很负 → $\alpha\approx 1$；
  - $W_b$ 的偏置很负 → $\beta\approx 0$；
  - 输出投影初始化为 0 → 训练开始时完全不改变原模型（同 LoRA 的零初始化）。

### 3.2 谁写、谁读

- **写**：只有 `[SUM]`。它通过前面各层的注意力已汇总本帧的视觉和 `[PROPRIO]` 信息。
- **读**：所有 token 都可以用自己的 q 读 S 并加到残差上；4 个 readout 头读到的是本帧 `[SUM]` 写入后的 S。
- **实现上的好处**：记忆的递归只发生在每帧一次（60 秒 = 300 步），帧内所有 patch token 读的是同一个 S，直接矩阵乘即可。**不需要修改 fla kernel**，可以用普通 PyTorch 实现，也方便反传。

### 3.3 与 discard / persist 的关系

- readout token 不写记忆分支，所以记忆分支天然不受"惯性"影响；主干里 readout 是否保留（persist / discard）仍按流式方案第 4 节另行比较。

## 4. 按项寻址

delta rule 本质是一张可覆盖的键值表：用同一个 key 写入，旧值被替换。按项寻址让每个步骤项占一个固定的 key 方向。

### 4.1 写入

- **key**：$k_t = \mathrm{norm}\big(W_{\text{addr}}\, h(\texttt{[STEP]}_{i_t})\big)$。$h(\texttt{[STEP]}_i)$ 是前缀里第 i 项在该层的 hidden state（已缓存，整条 episode 不变）；$i_t$ 是本帧正在做的那一项。
- **value**：由 `[SUM]` 的 hidden 生成，表示这一项的状态（完成次数、是否被破坏）。
- **β**：事件帧（完成、回退）高，其余帧低；由 `[SUM]` 计算，并受第 5 节的门监督约束。
- **α**：计数槽在整条 episode 内 ≈ 1。

### 4.2 读出

- 用 $q = \mathrm{norm}(W_{\text{addr}}\, h(\texttt{[STEP]}_i))$ 读出第 i 项的状态，对每一项各读一次，接 MLP 得到该项的有序计数 $P(c_i\ge r)$，作为 `[CNT]` 的输入。
- readout token 的普通读取（3.2）同时保留，用于 `[STG]` `[P]` `[M]`。

### 4.3 两档寻址

| 档 | $i_t$ 来源 | 用途 |
|---|---|---|
| 硬寻址 | 训练时用标注的阶段；推理时用 `[STG]` 的 argmax | 先验证"按项存计数"是否可行 |
| 软寻址 | $k_t=\mathrm{norm}\big(\sum_i \pi_i\, W_{\text{addr}} h(\texttt{[STEP]}_i)\big)$，$\pi$ 为 `[STG]` 的分布 | 端到端，容忍指针不确定 |

- 硬寻址训练时从"标注阶段"逐步过渡到"`[STG]` 预测"（scheduled sampling），避免训练和推理的寻址不一致。
- 对 $W_{\text{addr}}$ 加正交正则：同一任务内不同项的 key 两两点积接近 0。步骤数远小于 128，容量足够。

### 4.4 对应的能力

| 需求 | 在记忆里怎么体现 |
|---|---|
| 重复任务计数 | 第 i 项每完成一次，用 key_i 写入新计数，旧计数被替换 |
| 回退 / recover | 成果被破坏时，用 key_i 写回"未完成"或计数减一 |
| 时序错误 | 读出各项状态：前面的项未完成、后面的项已完成 |
| 长时序 | 计数槽 α≈1、非事件 β≈0，保持靠结构而非梯度 |
| 子任务内进展 φ | 主要由最近 N 帧的 full attention 和 DeltaNet 提供；可选一个"局部槽"在子任务边界处清空 |

## 5. 监督

总损失：

$$\mathcal L = \mathcal L_{\text{readout}} + \lambda_{\text{mem}}\,\mathcal L_{\text{mem-read}} + \lambda_{\text{gate}}\,\mathcal L_{\text{gate}} + \lambda_{\text{alias}}\,\mathcal L_{\text{alias}} + \lambda_{\text{orth}}\,\mathcal L_{\text{orth}}$$

| 损失 | 内容 | 作用 |
|---|---|---|
| $\mathcal L_{\text{readout}}$ | 现有 4 个 readout 头的损失 | 主损失 |
| $\mathcal L_{\text{mem-read}}$ | 每帧按 4.2 从记忆读出每一项的计数和状态，与标签比较 | 直接要求"记忆里能读出 k"，防止只满足门约束却没写有用内容 |
| $\mathcal L_{\text{gate}}$ | `[SUM]` 的 β：事件窗口内 $\max_t \mathrm{logit}(\beta_t)\ge m_+$，非事件帧 $\mathrm{logit}(\beta_t)\le m_-$；计数槽 $-\log\alpha_t\le\epsilon$ | 规定写入时机和不遗忘 |
| $\mathcal L_{\text{alias}}$ | 重复任务里画面几乎相同、k 不同的两帧，其记忆读出必须可区分（对比损失） | 针对视觉混叠 |
| $\mathcal L_{\text{orth}}$ | 4.3 的 key 正交正则 | 减少项之间的干扰 |

- 门损失在 logit 上用带 margin 的 hinge，避免 sigmoid / softplus 饱和导致梯度消失；$\lambda_{\text{gate}}$ 前期较大、后期退火，只作先验。
- 标签（不新增人工标注）：
  - 事件帧：子任务完成（分段终点）、失败 / 回退的起止（回退标注）；
  - 事件窗口：事件帧前后 ±w 帧（初始 w 对应 0.4 秒），容忍边界误差；窗口外 2w 以内的帧不加门损失；
  - 每项计数和状态：由分段和回退标注推出，与 `[CNT]` 标签同源。

## 6. 训练

- **写入靠密集监督当场学会**：完成事件之后的几帧，$\mathcal L_{\text{mem-read}}$ 和 `[CNT]` 就要求计数加一，梯度只需回传几帧。
- **保持靠结构给出**：计数槽 α≈1、非事件 β≈0，长时间保留不依赖长链梯度。
- **截断反传**：主干在短段内反传；记忆分支状态很小，可以单独跨更长的段反传。参考 μVLA（长链 BPTT 反而更差）和 ReMem-VLA（可训练循环路径易失去记忆），记忆分支的截断长度作为超参，从短到长扫。
- **主干**：冻结或 LoRA；记忆分支、`[PROPRIO]`、`[SUM]` 的 embedding、readout 头全量训练。
- **数据增强**沿用流式方案第 5 节：
  - 循环拼接，覆盖 12–16 次重复；
  - 时间扭曲，防止记忆退化成计时器；
  - 乱序拼接，训练时序错误；
  - 回退附近加权。

## 7. 阶段 A：测量（预训练 head，不训练）

用途：判断预训练 head 里有没有可直接利用的记忆；也为第 8 节"改造已有 head"的消融挑选 head；训练后用同一套工具检查记忆分支。

### A.1 设置

- 模型：Qwen3.5-2B 与 4B 原始权重，相同 episode、采样频率和输入分辨率；之后对各自微调后的 checkpoint 重复。
- 数据：需要事件标签。用恢复数据中带子任务分段和回退标注的 episode，或给已测的 RoboDojo episode 补事件标注；另取 ContextProgress 重复子集。
- 输入：指令 + 步骤列表前缀，之后按 5 Hz 逐帧追加三视角 448²。
- 实现：在 `Qwen3_5GatedDeltaNet` 上挂 forward hook，按源码公式还原 α、β；层次 2、3 另需 k、v 或各层状态。Linux + GPU，fla chunk kernel。

### A.2 指标

| 层次 | 内容 | 输出 |
|---|---|---|
| 1. 衰减上界 | 第 $i$ 帧末 token 到第 $t$ 帧末 token 的 $\prod_j \alpha_j$ | 每个 head 的保留曲线、半衰期 |
| 2. 精确残留 | 按线性展开 $S_t=\sum_i \beta_i v_i k_i^\top\prod_{j>i}\alpha_j(I-\beta_j k_j k_j^\top)$，第 $i$ 帧各项之和的范数占比 | 含 β 擦除的残留曲线 |
| 3. 可读性 | 线性探针：从第 $t$ 帧的各层状态 / hidden 预测"Δ 帧前是否发生完成事件"及 k | 探针准确率随 Δ 的曲线；DeltaNet 层 vs full attention 层 |

附带：α、β 按 token 类型分组；事件帧与静止帧的 β 对比；残留平台对应的长期保留方向（对状态传播矩阵做 SVD）。

### A.3 产出

- 候选 head 按"含 β 的残留 + 可读性"排序，α 只作粗筛。
- 若有 head 在事件处 β 已明显升高、且探针能长程读出 k，可作为记忆分支 key / value 投影的初始化参考。

## 8. 实验组与对比

| 组 | 内容 |
|---|---|
| B | 基线：只训 4 个 readout 头（LoRA），full attention 看全历史 |
| M1 | 记忆分支 + 硬寻址，full attention 限制为最近 N 帧 |
| M2 | M1 换成软寻址 |
| M3 | M2 + `[PROPRIO]` 写入 |
| M2-full | M2，但 full attention 看全历史 |
| 参照 | oracle-k（直接输入真值 k）作为上限 |

消融（在 M2 上）：

| 消融 | 回答的问题 |
|---|---|
| 去掉 $\mathcal L_{\text{gate}}$ | 写入时机能否只靠读出损失学会 |
| 去掉 $\mathcal L_{\text{mem-read}}$ | 记忆内容是否需要直接监督 |
| 自由 key（不寻址，key 由 `[SUM]` 生成） | 按项寻址本身的贡献 |
| 允许 patch token 写入记忆分支 | 写入次数对覆盖的影响（复现测量报告的问题） |
| 改造已有 head：在选中的预训练 head 上监督 α、β（原 C 方案），再加帧摘要写入（原 D 方案） | 新增分支 vs 复用主干 head |

指标：

- **k 的长程准确率**：按"最近一次事件距今多少秒"分桶；
- **长度外推**：训练覆盖最多 N 次重复 / T 秒，测试 2N、4N 次与 2T、4T 秒；
- **回退**：回退后计数是否正确恢复，以及恢复所需帧数；
- **时序错误检出率**；
- **结果不可见的重复**：单独统计（无灯按钮、遮挡类）；
- **进度指标**：p 的 MAE、回退检出率与时差、停滞检出率，不得低于 B；
- **记忆行为**：用阶段 A 的工具检查记忆分支的残留曲线和事件处 β；
- **开销**：单步延迟与缓存大小（M1–M3 的缓存应不随长度增长）；
- **预训练能力**：少量通用视觉问答样本上是否明显退化。

判断：

- M1 明显好于 B → 专用记忆 + 寻址有效；
- M2-full ≈ M2 → full attention 的全历史不是必要的，可用固定大小缓存；
- M2-full 明显好于 M2 → 记忆分支还不足以独立承担长程信息；
- "改造已有 head"≈ M2 → 可以不加新参数，直接复用主干。

## 9. 风险

- **漏写不可恢复**：某次完成没被写入，k 就永久错 1。结果可见时 readout 头可从最近帧纠正；结果不可见时只能依赖 `[PROPRIO]` 等额外信号。
- **寻址错误**：`[STG]` 指错项时会写到错误的槽。软寻址可以缓解，但也可能把计数分散到多个槽；需要单独统计"写错槽"的比例。
- **门只是必要条件**：β 高只保证"写了"，所以必须配合 $\mathcal L_{\text{mem-read}}$。
- **标注边界误差**：用事件窗口和"窗口内至少一帧"的损失缓解。
- **步骤列表依赖**：按项寻址需要步骤列表；没有步骤列表的任务退化为自由 key。
- **自举的循环**：若之后用模型预测更新标签（见 [progress_bootstrap.md](../methods/progress_bootstrap.md)），门目标和计数标签随之改变，需固定一份人工核对过的验证集。
- **full attention 窗口过短**：φ 和"从当前帧纠正 k"依赖最近几帧，N 要在实验中扫。

## 10. 执行顺序

1. 补事件标注（恢复数据，或给已测的 RoboDojo episode 补标）。
2. 阶段 A 层次 2、3：全部 head 的含 β 残留排序、事件处 β 对比、可读性探针。
3. 训练基线 B。
4. 实现记忆分支（PyTorch，按帧递归）+ 硬寻址，训练 M1；在 ContextProgress 重复子集上看 k 的准确率和长度外推。
5. 软寻址 M2，加入回退和时序错误评测；跑第 8 节的消融。
6. M2-full 对照，确定 full attention 窗口。
7. M3：加入 `[PROPRIO]`，专测结果不可见的任务。
8. 汇总第 8 节的对比。

## 11. 2026-10-22 RoboDojo 验证记录

- 已完成 2B / 4B 的层次 1 测量：各 9 条轨迹、786 帧，5 Hz、三视角 448²；另在 fasten_screws 前 60 秒，对各 4 个慢 α head 做层次 2 的逐帧写入分解。正式对比统一使用通过数值检查的 FP16 路径。
- 选定 head 的 10 秒 α 上界中位数为 98.36%–99.99%，计入 β 后的写入范数残留中位数为 1.73%–46.27%；最大状态重建相对误差 0.316%。不能只按 α 判断实际残留，也不能据此推断语义可读性。
- 本轮按约定先验证 RoboDojo，未使用事件标签，未运行可读性探针或 B / C / D 训练。完整指标、限制与复现命令见 [实验报告](../evaluation/gdn_gate_measurement_robodojo_20261022/report.md)。
