# Proposal：价值函数（RECAP 式剩余步数）及其评估

> 版本：2026-10-13。由 [proposal_v5_combined.md](../archive/proposal_v5_combined.md) 拆出。状态进度打分器见 [proposal_progress_2026-10-13.md](../archive/proposal_progress_2026-10-13.md)；用下游任务评估的计划见 [eval_plan.md](../evaluation/eval_plan.md)；相关工作见 [research.md](../literature/research.md)。

## 1. 问题

- 进度模型回答“现在做到哪一步”，不回答“从这里出发能不能做完、还要多久”。
- RECAP（π*0.6）的价值函数回答了这个问题，但它是整个任务级的，失败只用一个大常数表示，主要用来给训练数据算优势。
- 失败预测（SAFE、FailureSpot）只回答会不会失败，不回答还要多久。
- 真实失败只有终局分数，没有逐帧标签。

## 2. 打分器

- **回答**：从当前状态出发，还要多久做完当前子任务（或整个任务，见 3.3 的待定项）。
- **通用标准，不针对某个 VLA**：用所有数据（示范、遥操作、各种策略的 rollout）一起标，学到的是数据混合的平均。π*0.6 的价值函数也是这样训练的（“数据集所代表的策略”，即人和历次策略的混合）。介入和报错按统一标准判断，像工厂规则一样，不按执行者的能力区别对待。
- **输出**：剩余步数的分布，0…H_k 若干档 + **失败档**，按档分类、交叉熵训练。
- **可读出**：
  - **H 步内完成的概率**：非失败档之和；
  - **预计剩余步数**：期望；
  - **RECAP 形式的价值**：负的预计剩余步数。
- **输入**：尚未确定；单帧，或加最近若干帧。若使用历史帧，“卡了很久”本身就是这个策略真的卡住的证据，不变性检验（4 节 E）只对单帧版本作硬性要求。

## 3. 标签

### 3.1 子任务
与 [proposal_progress_2026-10-13.md](../archive/proposal_progress_2026-10-13.md) 3.1 相同：有序子任务，各有完成条件；**当前子任务 = 第一个完成条件不成立的子任务**，前面的成果被破坏时自动退回。真机的子任务分界由 VLM（Astra）标注，只用来生成标签。

### 3.2 剩余步数标签
- 定义：$r_t = b_k(t) - t$，即当前子任务 k 实际还用了多少步完成。
- 每个子任务的时限 $H_k$ 取成功执行耗时中位数的 2–3 倍，用来区分“慢”和“失败”。

| 情况 | 标签 |
|---|---|
| $r_t \le H_k$ | 第 $r_t$ 档 |
| 观察满 $H_k$ 步仍未完成；或 episode 因任务失败 / 无法挽回而结束 | 失败档 |
| episode 因总时长用完而结束，观察不满 $H_k$ 步 | 截断：损失取 $-\log P(r > T_{\text{end}}-t)$，或丢弃 |
| 失败后恢复并在 $H_k$ 内完成 | 照常记步数（恢复时间算在内） |
| 完成后被破坏 | 当前子任务退回，按退回后的子任务计 |

**失败轨迹**：已完成的子任务照常标步数；只有结束时还没完成的那个子任务进失败档（总时长用完时，最后 $H_k$ 帧为截断）。失败的不一定是最后一个子任务（可能因退回落在更早的子任务上）。例（$H_k$=6，子任务 3 没完成）：

| 帧 | 0–4 | 5–10 | 11–19 | 20–25 |
|---|---|---|---|---|
| 子任务 | 1 成功 | 2 成功 | 3 未完成 | 3 未完成 |
| 总时长用完结束 | 4…0 | 5…0 | 失败档 | 截断 |
| 判定失败结束 | 4…0 | 5…0 | 失败档 | 失败档 |

**两个约定**：
1. 按**固定的** $H_k$ 归一化，不按这一次的实际耗时归一化，否则又变回 t/T；
2. **所有数据都可以标，但必须包含失败和恢复**。只有成功示范时，剩余步数与 t/T 没有区别。用混合数据时注意：
   - 学到的是数据混合的平均：同一个状态，专家 3 步救回、弱策略超时失败，模型学的是两者按出现频率的平均；数据配比变了，数值也会变；
   - 不同来源的速度不同（遥操作和 VLA、不同控制频率），步数要换成秒，或按来源归一化；

**标签不跳，预测会跳**：单条轨迹的标签只会逐步递减（例如掉了一次，仍是 9 8 7 … 0）。模型学的是“从这个状态出发平均还要多久”，所以预测会在掉落处跳变（搬运中平均剩 2.8 步，掉在桌上平均要 5 步）。单条标签噪声大，因此预测分布。

### 3.3 与 RECAP 的关系

**RECAP 的定义**（π*0.6 论文式 (5)）：

$$r_t=\begin{cases}0 & t=T \text{ 且成功}\\ -C_{\text{fail}} & t=T \text{ 且失败}\\ -1 & \text{其他}\end{cases}$$

- MC 回报：成功时为 $-(T-t)$；失败时为 $-(T-t) - C_{\text{fail}}$（前面的 −1 照样累加，终点再减一个大常数）。
- 按每个任务的最大 episode 长度归一化到 (−1, 0)；价值函数本身也是分布式的。
- **负号只是 RL 的约定**：目标是最大化回报，每步 −1 使“越快完成”等于“回报越高”；后面的优势 $A = \sum r + V(o_{t+N}) - V(o_t)$ 和 “Advantage: positive / negative” 都要求数值越大越好。对打分器本身，正负号没有影响。

**对比**（例：T=10，C_fail=100；我们按单个子任务、H=15）：

| 帧 t | 0 | 3 | 6 | 9 | 10 |
|---|---|---|---|---|---|
| RECAP，成功 | −10 | −7 | −4 | −1 | 0 |
| 我们，成功 | 10 | 7 | 4 | 1 | 0 |
| RECAP，失败 | −110 | −107 | −104 | −101 | −100 |
| 我们，判定失败结束 | 失败档 | 失败档 | 失败档 | 失败档 | 失败档 |

成功时两者只差负号。区别在于：
1. **失败段里 RECAP 的标签仍随时间上升**（−110 → −100），残留时间信息；失败档在整段失败里不变。
2. **RECAP 把“慢”和“失败”放在同一条数轴上**；我们用 $H_k$ 分开。
3. **RECAP 没有截断**，时间用完也当失败；我们只用下界损失。
4. **范围**：RECAP 到整个任务结束；我们到当前子任务完成，被破坏时退回。

**待定**：做子任务级还是任务级；失败用失败档还是 $-(T-t) - C$。若改成任务级、失败用 $-(T-t) - C$、时间用完当失败，就与 RECAP 完全相同，只差负号，此时称为“RECAP 价值”即可。

### 3.4 高精度测试集（仿真）
- **同状态重跑**：恢复某一时刻的状态，VLA 重跑 K 次，得到真实的剩余步数分布和完成概率（期望值，会在掉落处跳变）。
- **双胞胎扰动**：同一时刻复制两份，一份正常继续，一份人为破坏（或帮一把），方向由我们制造、确定无疑，再重跑核实。

### 3.5 数据
- 仿真 VLA rollout：RoboDojo，必要时 LIBERO / RoboTwin；π0.5 + XPolicyLab 多策略 + 不同检查点，加扰动增加失败。
- 事件标签同 [proposal_progress_2026-10-13.md](../archive/proposal_progress_2026-10-13.md) 3.3。

## 4. 评估

**主指标是下游任务的成功率**（RL、介入时机），见 [eval_plan.md](../evaluation/eval_plan.md)。下面的检验用于开发时诊断。

**原则**：直接用实际结果打分；失败时剩余步数应**上升**；比较要在相同时间点上进行，避免失败局更长带来的“数时间”混杂。

| 类别 | 检验 |
|---|---|
| A. 结果评分 | 似然 / Brier（含失败档、处理截断）、校准、C-index、完成预测 AUROC |
| B. 事件级 | 掉落检出率与延迟、恢复检出率、停滞一致率、误报率（正常区间 + **自愈区间单独统计**） |
| C. 方向 | 上升 / 停滞 / 下降 F1 |
| E. 不变性* | 插入暂停帧、变速、同状态不同时刻 / 路径、无关视觉变化，输出不变 |
| F. 双胞胎扰动 | 被破坏的更差、被帮助的更好 |
| G. 鞅检验 | 预测的变化不应能被过去和已过时间预测（识破“数时间”） |
| H. 高精度对照 | 与同状态重跑的经验分布的距离 |
| 参考 | 偏序（D）、VOC |

\* 只对只看单帧的版本作硬性要求。字母沿用合并版 proposal 的编号。

**评估设置**：我们的 rollout + 事件 + 重跑测试集；划分见过 / 没见过的任务、见过 / 没见过的 VLA（检验通用标准在新 VLA 上是否依然有效）、仿真 / 真机。

**Baseline**：每个任务单独训练的 RECAP 价值、ValueFormer、SAFE / FailureSpot 式 probe、t/T。另用相同标签重训 baseline 架构，区分“标签更好”和“模型更好”。

## 5. 与已有工作的区别
- **RECAP**：整个任务级、失败为 $-(T-t) - C$、只用于训练 → 子任务级、失败单独成档、处理截断和退回、独立打分器（见 3.3，是否保留这些区别待定）。
- **SAFE / FailureSpot**：只回答会不会失败 → 剩余步数同时给出会不会失败、还要多久。

## 6. 待确认与风险
- **待确认**：子任务级还是任务级（3.3）；输入格式；各子任务的 $H_k$；RoboDojo 能否回到中间状态（重跑测试集需要）；XPolicyLab 能否本地批量运行。
- **风险**：单条标签噪声大（预测分布 + 重跑测试集）；数值随数据配比变化（下游只用变化量、排序和分位数）；仿真与现实差距（真机单独报告）。
